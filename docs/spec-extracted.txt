1. System Architecture & Strategic Vision
The All-in-One Model Context Protocol (MCP) Gateway provides a unified, secure orchestration tier for multi-
agent environments. Rather than hosting fragmented MCP tool servers across disparate endpoints with
scattered API credentials, this platform encapsulates all runtimes (Node.js, Python, Go, and binary processes)
within a single master Docker container. The system serves as a smart security shield, presenting a single entry
point (`/mcp/v1`) while strictly enforcing zero-trust discovery, key-scoped tool visibility, and remote agent
delegation.

3. Navigation Menu & Zero-Trust Discovery
The MCP gateway functions as a dynamic, intelligent navigation menu for AI agents. When an agent initializes,
it can query search and listing endpoints to discover available tools. Crucially, the catalog response is censored
at the gateway layer based on the agent's API key permissions—unauthorized tools are completely invisible.

 Discovery Vector           JSON-RPC Method                     Scope Filtering Mechanism              Visibility Mode

 Catalog Search             `tools/search`                      Filters vector search results           CENSORED
                                                                against permitted API key scopes.

 Menu Enumeration           `tools/list`                        Returns schemas *only* for tools        MASKED
                                                                granted to the agent's API key.

 Server Query               `servers/list_permitted`            Lists accessible sub-servers;           ZERO-TRUST
                                                                unpermitted servers are hidden.

 Direct Execution           `tools/call`                        Executes known tools directly           DIRECT
                                                                without requiring re-discovery.

 Agent Delegation           `agents/delegate`                   Routes request to an external           DELEGATED
                                                                observer bot or remote agent
                                                                harness.


4. Default-Hidden High-Privilege Safeguards

  High-Risk & Root Privileged Tool Isolation
  Certain MCP sub-servers provide powerful capabilities—such as root shell access, production database drop
  commands, or infrastructure modifications. By default, these tools are marked as `HIGH_PRIVILEGE` and are omitted
  from all generic search and listing requests. An agent cannot see or infer their existence unless its API key explicitly
  holds a signed grant for that specific tool ID.


Discovery & Repeat Call Optimization Rules
  Dynamic Navigation Menu: On initial bootstrap, agents query `tools/search` or `tools/list` to populate their
  internal tool availability tree.
  Direct Invocations for Frequent Tasks: Agents store tool signatures in memory. For repeat operations,
  agents bypass search and execute `tools/call` directly via the gateway.
  Invisible Rejection: Calling an ungranted tool ID yields a standard generic `Tool Not Found` or structured
  `Access Denied` response, preventing key probing.
  Transient Scope Escalation: Agents can request supervisory elevation, generating an audit ticket for
  human or Chief AI approval.

  API Key Generation Protocol
  Keys are cryptographically generated using SHA-256 hashed tokens with embedded metadata. When creating a key
  via the Web UI or Master API (`POST /mcp/v1/admin/keys/create`), administrators explicitly check server IDs, tool
  masks, and set expiration limits.

10. Interactive Sandbox & Testing Playground

  Live Payload Testing & Diagnostic Sandbox
  The Web UI includes an interactive API playground that allows administrators to send test JSON-RPC payloads directly
  to any hosted sub-server or sub-agent. The playground simulates execution using specific Agent API key contexts,
  displaying raw request/response payloads, latency breakdowns (Gateway overhead vs. Sub-server time), and scope
  verification status.


Admin Capabilities Available in Web UI
  One-Click API Key Provisioning: Generate new keys with checkboxes for server access, tool whitelisting,
  and delegation rights.
  Live Log Streaming: WebSockets-powered real-time terminal window showing stdout/stderr streams for all
  running sub-processes.
  Hot Secret Rotation: Update third-party API credentials in the vault with zero downtime; running processes
  reload variables seamlessly.
  Instant Emergency Lockout: Kill switch button to revoke an API key or isolate a compromised sub-server
  instantly.

11. Protocol Extensions & JSON-RPC Schemas
The gateway extends standard Model Context Protocol JSON-RPC 2.0 messages to support scope-filtered
discovery, catalog search, and structured escalation error payloads.


        // Request: tools/search with Query Filtering { "jsonrpc": "2.0", "id": "req-102", "method":
  "tools/search", "params": { "query": "database postgres query", "limit": 5 } } // Response:
  Filtered to permitted tools only (Zero-Trust) { "jsonrpc": "2.0", "id": "req-102", "result": {
  "tools": [ { "name": "postgres_read_query", "description": "Execute read-only SQL SELECT
  statements", "server_id": "postgres-mcp-v1" } ] } }



12. Access Denial & Escalation Error Schema

        // Response: Structured Access Denial (-32001) { "jsonrpc": "2.0", "id": "req-205", "error":
  { "code": -32001, "message": "Access Denied: Agent 'mcp_ag_sales' lacks permission for
  'db_drop_table'.", "data": { "status": "FORBIDDEN", "reason": "HIGH_PRIVILEGE_RESTRICTION",
  "ticket_id": "esc-20261029-8812", "escalation_supported": true } } }


Automated Agent Escalation Parsing: When an agent receives error code `-32001` with `escalation_supported: true`,
autonomous agents configured with reasoning capabilities can parse the `ticket_id` and issue an approval request to a
supervisory bot (`mcp_sup_...`) or human admin via `POST /mcp/v1/escalations/request`.
